# Development

Open the [project index](../../../development/README.md) to choose a Linear home.
This Lane holds technical builds, tests, maintenance and engineering proof.
Offers and audiences stay in the service Lanes.

Keep task names plain. Put build detail, TDD seams and finish checks below the
short summary. Use the [task rules](../../agents/issue-tracker.md) and
[writing rules](../../harness/writing-rules.md).

For service work, link the Linear build to the Asana outcome. Asana shows
Jerami's next action; Linear keeps the deeper execution record. Use native
blockers only for work that really gates another step.

Keep deadlines separate from planned work dates. Check proof before closing
children, then the parent. An initiative or label never starts work.
