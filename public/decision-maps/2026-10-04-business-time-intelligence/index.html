1 · Choose the smallest durable system

Glaze is the main desktop application for saved projects, work logs, corrections, reports and learning. Raycast supplies quick commands/forms. Use AppKit/ApplicationServices for collection, GRDB over system SQLite for persistence, and a versioned native interface for both surfaces. One Swift domain module owns interval accounting and business math; reporting and learning consume its canonical outputs.

The installed Glaze 0.14.3 SDK uses a macOS WebView and Node backend. Its supported native-sidecar path compiles Swift source and bundles it for installed apps. The tracker retains an independent native app lifecycle; a child process tied to Glaze quit does not meet that requirement. Verify signing, permissions and login launch on the actual installed app. Glaze native integration.

2 · Collect context with explicit limits

Timing's useful mechanics are foreground-only samples, idle gaps, project rules and editable attribution. Its FAQ describes one-second polling, a three-minute idle default, Automation for app-specific context, and a CGWindow title fallback requiring Screen Recording. Reproduce the mechanics needed for attribution; exclude productivity scores, sync, calendars and broad integrations.

Coverage target: at least 95% of eligible active work time receives the correct project automatically on a representative, manually reviewed workday. Eligible time excludes idle, paused and privacy-excluded periods. Report basic app/time coverage separately from automatic project attribution; manual labels cannot inflate the automatic figure. Normalize work paths to approved root plus relative path. Exclusions run before persistence. Default raw-context retention: 30 days; reviewed sessions/financials remain until deletion.

After retention expiry, clear captured context; retain timing and reviewed allocations. Rules can replay only retained context.

No Full Disk Access request. No screenshots, recordings, clipboard data, microphone or camera. Capture adapters are read-only; Accessibility's broad grant does not authorize UI manipulation.

4 · Teach the money and time separately

Gross revenue G is the project price or rate × billed hours. Show quote, billed and received status. Actual tracked hours H never determine billed revenue unless the user explicitly uses them as billed hours.

Platform fee P = fee base × entered fee percentage Direct project costs D = production costs + P + other project fees Gross profit GP = G − D Gross margin = GP / G × 100% Operating profit OP = GP − allocated overhead O Operating margin = OP / G × 100% Estimated take-home = OP − entered tax estimate Revenue/hour = G / H Gross profit/hour = GP / H Operating profit/hour = OP / H Economic profit = OP − H × target hourly value V

Project-specific fees belong in D for this management view. Show production costs and each fee separately before their total. Your own labor is an opportunity-cost line, never default COGS. Explain: cash profit is money after expenses; economic profit also accounts for the value you assign your time.

Optional tax scenario: entered reserve percentage × max(OP, 0), or an explicit amount. Mark it an estimate; no tax rules or deduction logic. If overhead is absent, label OP “overhead excluded.” Unknown expenses stay unknown; zero is an explicit input. Margins are unavailable when G = 0; hourly measures are unavailable when H = 0. Losses and negative economic profit remain visible.

$500 revenue − $100 costs = $400 gross profit and 80% gross margin. Four hours produce $125 revenue/hour and $100 gross profit/hour. With no overhead and a $100/hour labor target, economic profit is $0. You kept $400 cash before taxes; the job exactly met your time target.

Catena example: 8h 17m = 8.2833 hours. $280 revenue and $12 costs produce $268 gross profit, $33.80 revenue/hour and $32.35 gross profit/hour. Gross margin is 95.71%. Operating profit requires an overhead choice.

Proposed billing adapter: normalizeBilling(sourceRecord) → BillingInputs. The calculator accepts normalized price/rate, billed hours, gross billed, fee amounts, currency and provenance. It knows no Upwork credentials or endpoints. Manual input is the sole V1 adapter.

Upwork-ready fields include contract ID, hourly rate, fee percentage/base, billed hours, actual tracked hours, gross billed, each transaction/withdrawal fee and actual net received. Project fee estimates and settled fee amounts are alternatives, never added twice. Withdrawal fees shared by projects need an explicit allocation; do not charge the full fee to every project.

Estimated net receipts = G − platform/transaction/withdrawal fees. Actual net received is a separate settled input. Effective net received/hour = actual net received / H, or a clearly labeled estimated counterpart. Net receipts do not deduct production costs; profit/hour does. Upwork documents contract-specific fees from 0% to 15%; no universal 10% default.

5 · Make manual mode useful first

“Project Economics” opens a form for Client, Project, Job Price, Hours, Direct Costs, Platform Fee % and Other Fees. Submit saves dated inputs and immediately pushes the formula/result view. Expanded inputs offer hourly billing, billed hours, transaction/withdrawal fees, overhead, tax scenario and target time value.

Independent commands: Start Project, Stop Project, Current Project, Project Economics, Today and This Week. Start closes a prior selection atomically; Stop is idempotent. With collection enabled, Start sets project intent and totals only accepted active time. With collection disabled, it starts a declared elapsed timer. Stop shows elapsed time for review before saving. Sleep/AFK cannot be assumed excluded in this mode. Never add both representations of the same period.

Today/This Week show per-project active time, manual time, idle, unassigned and missing coverage. Project economics uses lifetime project hours by default; a daily report must not divide the full job price by today's partial hours without labeling that assumption. Duration-only entries are date-bound and marked manual.

Selected-project actions open economics, correct time and propose rules. Use native Form/List/Detail, ActionPanel sections, emoji actions, stable IDs and pushed child views with explicit refresh. The existing Prospect Workspaces reference has these conventions and Raycast API 2.6.2; the installed app reports 2.6.2.0. Verify UI behavior during build.

Script Commands are suitable CLI shortcuts but accept only three arguments. Rich forms need an extension. Raycast exposes foreground app identity and Finder selection, not a durable all-app document stream. BrowserExtension.getTabs supplies URLs, but “active” means active in each window; it does not identify the sole foreground window across every browser. Do not use it as the background collector or read page content.

Raycast LocalStorage is encrypted and scoped to one extension; its documentation excludes large datasets. Store display/filter preferences there. The external agent cannot use that storage API. SQLite owns durable records. Local file I/O/child processes are supported by Raycast's Node environment; protected directory access can require permission for its parent app.

7 · Build only after the research gate
  1. Approved sequence: foundation → manual workflow → Financial Engine → SQLite and Glaze/Raycast interfaces → tracker/idle → adapters and attribution → reporting → learning → future billing adapter boundary. Native Linear blockers enforce the route.
  2. Manual vertical slice: Glaze workspace/Raycast form → shared native interface → SQLite → canonical economics. TDD at the public financial/persistence boundary. Accept the $500/$100/four-hour example, zero denominators, fees once, negative profit and persistence after restart. Financial unit tests pass before reports or learning consume the engine.
  3. Compatibility spike: stable native app identity; permission denial/revocation; app/title/path/browser matrix on this Mac. Test Premiere, Finder, Figma, Slack, terminal/editor and the browsers used in current work. Probe alternate routes for missing context. Screen Recording stays optional for CGWindow title metadata; no screenshots or recordings. Record each adapter result.
  4. Tracker: app switches, five-second reconciliation, idle split, pause, sleep/wake, lock, crash checkpoint recovery. Verify a controlled sequence against elapsed time. Raycast quit must not stop tracking; disabled login launch must be visible.
  5. Classification/review: Catena root, singleton-systems repo and scoped NFL Awards title rules. Test ties, client-only matches, partial corrections, rule replay and timer overlap. Reclassification must leave source evidence unchanged.
  6. Today/This Week and economics: interval union, timezone/DST boundaries, overhead allocation and source labels. Measure CPU/memory/database growth during a normal work session. Proposed targets: average CPU under 1%, resident memory under 100 MB, no unbounded context logs. Report measured results.

Use Raycast lint/build/typecheck and Swift tests at each meaningful slice. Keep financial and time-accounting tests independent of UI internals. Native permission/interaction proof is required; mocked AX tests cannot establish compatibility.

Verified local tools: macOS 27.0.1, Swift 6.4, SQLite 3.54.0, Hammerspoon 1.1.1. Installed presence does not prove runtime permission. Research did not activate collection or request grants.

Remaining unknowns: actual AX title/document exposure in editing apps; safe private-session filtering; sleep/lock behavior on macOS 27; signing identity and TCC attribution of the bundled helper; passive footage review; chosen retention and overhead allocation. Defaults are stated above. Missing metadata must trigger an alternate route while app-duration tracking continues. Manual mode remains available.

Excluded scope: invoicing, accounting, payroll, CRM, employee monitoring, screenshots/recordings, productivity scoring, Timing parity, tax preparation, LLM classification and Upwork OAuth/API work.

Build methods: Wayfinder for unresolved decisions; Backend Architect for service/data contracts; TDD and Implement for verified slices; Improve Codebase Architecture when existing module friction appears.
