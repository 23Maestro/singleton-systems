## What the reader sees

Start with a main-folder overview. Show a short name, a purpose drawing, and
1 sentence about what each folder does. Open a folder to see what is inside.
Open a file to read its source and follow supported links. Keep a clear way
back, search, and the folder tree. Group a large overview into small panels;
do not shrink every folder onto 1 crowded screen.

Lead with the job, such as Website, Guides, or Video Work. Keep the exact path
nearby or in the details. These labels do not rename files. Explain an unknown
folder only after reading its source; show `Not reviewed yet` when needed.
Mark areas that show a folder listing but do not yet offer file reading.

Put technical terms, hashes, raw data, and code behind `Source details`.
Keep the data available to open and copy. Preserve source words in the file
reader; write a separate plain summary when needed. A short summary must not
replace or alter the source.

## Build from facts

Use direct folder listings for the tree and document links for doc connections.
For code relationships, use Graphify on a small chosen code, schema, or config
scope, then read the matching source. Record hashes and check freshness before
reusing a graph. A whole-repo view is a long-term coverage goal; it is not a
request to send the whole repo through a model or flatten it into 1 graph.

Use Jev when choosing a new visual format. Keep the current expandable HTML/SVG
canvas unless the requested behavior needs a change. Jev does not replace the
drawing guide or the user's page choices.

Distinguish `Contains`, `Links to`, and a verified work step. A folder tree is
not a task flow. Never invent arrows, status, or delivery claims from file
names. Read the task owner when showing live work state.

Show the snapshot date and which areas are included. A partial map must not
claim to cover the whole repo. Build exports from an explicit set of allowed
paths. Leave out credentials, environment values, private mail, dependencies,
caches, Git internals, and generated output. Inspect each new content scope
before adding it to the hosted page. Do not follow links outside that scope
or upload raw source just because it exists on disk.
