## One owner

`skills/outreach` in the Singleton Systems repository is the source. Its
Markdown modules own the method. The installed personal `outreach` entry points
to this folder. The personal `gift` entry points to `references/gift-entry`.
Neither entry keeps a second policy copy. Resolve real paths before running
the helper. Business offers, client facts and task state stay with their owners.

The active workspace operating guide links this folder. Its Lane guides choose
the current offer. The shared weekday automation loads Outreach. Former Gift
calls still work through the small entry. The historical Claude Gift source
stays unchanged as an archive, not an active rule owner.

## Change and check

Edit this source. Keep 1 owner per rule. Update date code and scenario tests
when timing or stop behavior changes. Check connected-service behavior through
exact readback when an action is authorized. Do not call a local unit test proof
of a real draft, scheduled notice or send.

From the repository, run `npm run check:outreach` and `npm run check:skills`.
Use `npm run check:outreach:installed` for local entry identity. Full repository
checks and the 2-pass review remain required for code delivery.
The package check includes this source and the Gift entry. No new hook, service,
CRM, provider connection or automatic enrollment is needed.

## Review basis

The consolidation used source inspection, a Graphify code/config map and Jev's
explicit folder comparison. Jev selected the versioned skill folder; its scores
are relative and uncalibrated. That choice does not validate policy or grant
permissions. Source review found the hard lifetime cap in the helper and the
same rule repeated across Gift, Outreach and the saved schedule.

Graphify's map is a code relationship aid. It does not extract policy from
Markdown or prove live behavior. Generated maps and the old personal skill
backup stay outside Git in the verified HomeSSD references folder.
