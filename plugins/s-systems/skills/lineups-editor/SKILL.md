# Lineups editor

Use only for Catena Media Lineups. Use `s-systems:client-video-storyboard` for
shared intake, full reference review, transcript mapping and a reviewed Premiere
handoff. Other clients keep their own profiles and tools.

Read the treatment and motion references before transcript mapping or authoring.
Read `references/lineups-delivery-contract.md` before Premiere import or delivery.
Keep frame comments, online batches and sending in the shared review engine
for all clients and Figma/Unreal renders. This skill owns the Lineups review
stages and source-edit limits. Extraction does not prove hosted delivery.

## Episode gates

Before reporting a missing source or proposing a new build, follow the
prior-production lookup in `references/lineups-episode-lifecycle.md`.
Read the matching production handoff and closeout. A rule that rejects a saved
working source needs reconciliation; it does not prove the design is missing.

For every Catena Media Lineups edit, read
`references/lineups-treatment-system.md` before transcript mapping, asset
selection, Figma work, or Premiere mutation.

At episode ingest and closeout, also read
`references/lineups-episode-lifecycle.md`. Use one Asana task and one episode
record per video in the `Content Editor` project and `Catena` section. Set its
due date from the confirmed delivery deadline. Use the locked Pre-Figma and
Post-Figma review UIs. A team or topic is episode data; it cannot change the
shared UI or create a new option.

At the start of each Lineups episode, load `singleton-figma-system` for the
shared workspace standard. Plan simple episode titles and actual-workday labels
at exactly 300 px, a left-to-right row of episodes with wide gaps, and a spec
for each approved lane used. Keep loose source material on the existing asset
page. Apply this structure at the first authorized Figma build and preserve it
as work grows. Starting an episode does not bypass its scene and review gates.

Use the repository-owned review renderer and template lock defined in
`references/lineups-episode-lifecycle.md`. Run its review-template check before
preview publication or an authorized Vercel deployment. Keep photos above short,
timestamp-matched excerpts; production instructions stay in details.

Always attempt full-transcript discovery across all seven lanes after obvious
rankings/Quick Action opportunities. Bind the ledger to the transcript hash.
Record excerpts/timestamps, rejected possibilities or genuine no-fit outcomes;
keep asset search work explicit. Run the review progression Gate before pacing
and selection. Timing proof cannot replace discovery.

For missing artwork, read `references/lineups-asset-search.md`. Search Eagle,
then Google with the episode year and week. Inspect recorded source-page leads
with `scripts/firecrawl-source-inspect.py`. Its hook validates the episode
request before the helper reads the named Firecrawl key from macOS Keychain.
Keep returned image links as leads until the original photo is verified.

For the Figma path, Cinematic 2-up uses full photos with original backgrounds, both visible from
the opening frame, and the established top-left title. Never suggest cutouts
or Asset Swap for that option. Quick Action Photo requests 4.5 seconds, with
actual frame-rounded duration recorded separately. Preserve live Premiere trims
and source In/Out.

Use its seven lanes, approved options, automatic routing, action-first asset
rules, transcript-copy rule, pacing profile, pruning rule, and pre-Premiere
screenshot gate. Keep Jerami's working language to lane, option, and setting.
Figma implementation terms stay inside the Figma-system skill.

When a Lineups option needs Figma, load `singleton-figma-system` and read that
skill's `lineups-production-system.md` reference before building. Do not rebuild
an approved option from loose layers when its source component already exists.

Before the first Lineups Figma mutation, create and activate the scene manifest.
The manifest must already contain the verified transcript anchor, rational frame
rate, cue list, `entranceTimes`, approved Figma source, episode instance, and
motion ownership. The Lineups Figma file fails closed when no active manifest
exists. Do not build static compositions first and add timing later.

Read `references/lineups-motion-contract.md` for Whisper/Manim timing,
Rank Reveal motion and the Figma production contract. Current per-scene engine
routes in the treatment system take precedence over broad Figma-only wording.
Unreal review copies retain their own proof and pending production gates.

Stop before Figma when the transcript anchor, Manim timing validation, Figma
Motion tracks, or approved source cannot be named and verified. For Rank Reveal,
also require the normalized canonical source and its cumulative 10-to-1 state.
Only Rank 10 may animate the full board cascade. Ranks 9 through 1 animate only
the current team name and normalized logo while prior reveals remain visible.
