# Owners and offers

## Read live owners

The active repository's CODEX.md points to the operations guide. Its
`docs/operations/clients-and-outreach.md` owns record homes. Resolve this path
from the repository, never from the installed plugin directory. Without that
repository, ask for its location or use checked connected records; do not guess.

| Fact | Owner |
| --- | --- |
| Client identity and relationship | Supabase `contacts`, using the existing ID |
| Website inquiry | Supabase `client_inquiries.id` and `contact_id` |
| Sends and replies | Gmail or the original channel, by message/thread ID |
| Outreach events and sales history | Existing Outreach sheet and row's stable Lead ID |
| Accepted next action | Existing Asana task in the matching service Lane |
| Plugin build and proof | Linear Development task |

Load Outreach's tools-and-records reference for the sheet's current mapping.
If an opportunity has no native ID, retain its existing row/thread/task links.
Do not mint a new CRM ID. Keep separate offers at the same company separate.
Read the full relevant thread history, including later replies, before setting
a sales state. Record fields may lag the original channel.

For each recommendation carry these values in the answer or working context:
contact ID, opportunity ID or existing source links, Lane, offer ID, latest
event ID/time, checked-at time, sales stage, next-action task ID if one exists.
Unknown stays null. This is an input/output contract, not a new database.

## Editing

Current offer rules live in the operations Content Editor Lane. Recurring
weekly edits lead; sports work is occasional. New outreach starts in Tampa Bay.
Keep a current client's signed scope and price ahead of generic website tiers.

Read `lib/video-offers.ts` and the deployed homepage before quoting a public
tier. Use its stable IDs: `free-test-edit`, `four-video-bundle`,
`eight-video-bundle`. The 4 + 2 and 8 + 4 bundles differ by volume. Choose from
the buyer's footage and output need, then check capacity. Shorts are cutdowns;
new scripts, footage or custom animation need scope review. The free test is
bounded and uses supplied footage. Do not turn an unsolicited gift into unlimited
free work or treat an unfinished gift as a finished test edit.

## AI consulting

Read the operations AI Consulting Lane first. Its workflow-cleanup outbound
path is shelved until scope and process review. A live opportunity can still
receive problem-first help. Do not turn an editing pitch into an AI pitch.

Read `lib/site-offers.ts`, `lib/ai-workflow-offers.ts` and the deployed consulting
page for current scope and price. Stable IDs:

- `start-with-one-thing`: 1 simple first task in the client's own account.
- `build-it-for-me`: 1 more repeated workflow with tested examples and steps.
- `keep-it-working`: ongoing work and upkeep, only if that need exists.
- `build-my-ai-system`: a larger group of workflows with a working foundation.

The public page is not proof that a campaign is active or that clients have
bought a tier. Internal tools and unpaid collaborations are internal proof.
Check paid work records before claiming a client case study or sale.

## Tier choice

Use the smallest current offer that solves the stated problem. Show why it
fits, scope still needed, and what would change the choice. Unknown budget does
not mean low budget. A higher business stage does not force a higher tier.
Price changes, added guarantees and new tiers are proposals for review.
